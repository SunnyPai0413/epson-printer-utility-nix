# 已有设计决策

[Agent 索引](../AGENTS.md) · [架构](ARCHITECTURE.md) · [证据](VALIDATION.md)

本文整理现有实现的选择与理由，不增加开发流程或测试要求。

## 原生构建与版本分离

从保留的 Epson 源码构建原生 Qt GUI、CLI 和 daemon，避免运行未说明来源的上游二进制。
项目版本由 `VERSION` 管理；v1.0.0 不表示上游 Utility 1.1.3／Backend 1.3.1 升级，JSON schema 仍为 2。

## USB 与网络路径独立

ecbd 只管理所选 USB 设备，EPSCommonLib 自身处理 Epson 网络设备。
因此网络专用配置可以关闭 USB daemon；CUPS IPP 打印成功不构成原生网络维护的兼容性证据。

## 共享锁与单次维护

GUI／CLI／oneshot 维护和 ecblp 打印提交共享操作锁，FIFO 写入另有写入锁。
维护先取锁再复查空闲，消除仅检查一次状态后继续发送的竞态。
一次维护命令发出后最多约两分钟等待状态；失败／超时记为未确认，不自动重发，避免重复耗墨或重复输出。
Windows 维护数据经 ecblp 传输时使用同一写入路径，但这不证明整个设备动作期间的锁覆盖。

## FIFO 背压、取消与失败

大型打印数据可能让仍存活的 ecbd 读端长时间消费较慢，因此 ecblp 对活跃读端持续等待，并保留 CUPS 取消能力。
读端丢失或 I/O 出错则明确失败，记录阶段、errno 和 poll 事件，不重开 FIFO 或重放已经发送的数据。
既有证据包括字节一致性、取消和读端消失的 fixture；实机重叠行为的边界见验证记录。

## 持久运行权限

CUPS 后端可能仅保留 `lp` 组而丢弃补充组，单独增加用户组不足以保证 FIFO 可写。
模块通过 tmpfiles 的访问 ACL 和默认 ACL 同时覆盖重启与文件重建，避免依赖一次性 chmod／setfacl。

## 明确未知值

设备错误、警告与通信结果分别表达；成功收到设备故障不等于通信失败。
墨色来自实际报告列表，不按六色机型或数组位置推断 photo black；原始 ID、重复项和不同黑色保留。
不可读墨量输出未知，真实 0 保持 0，不伪造百分比。进纸计数仅按原生语义报告，不当作成功页数或废墨重置接口。
字段约定集中在 [JSON 文档](../docs/JSON.md)。

## 定时任务与界面等待

喷嘴 timer 默认关闭；`Persistent=false`、`Restart=no`，离线／忙碌／锁占用时跳过，不积压补打，不自动清洗。
GUI 在 worker 中等待维护，禁用重复提交，避免阻塞界面或在通信工作未结束时销毁对象。

## 两种打印队列与维护边界

普通 ESC/P-R 队列负责服务器端渲染，RAW 队列只转发 Windows Epson 原厂驱动生成的数据。
保留独立队列名，避免将原厂数据再次交给 Linux 渲染器。二者复用 ecblp/ecbd，不额外占用 USB 接口。
RAW 和传统后端依赖已弃用的 CUPS 2.x 功能；本项目没有提供 CUPS 3 迁移实现，用户限制见 [打印配置](../docs/PRINTING.md#cups-raw-弃用限制)。

Power Ink Flushing 由 Windows 原厂驱动提供；本项目自身仍只有喷嘴检查和普通清洗，不开放任意指令、EEPROM 或废墨计数器重置接口。
